# Design: demo-foundation

## Overview

Week 1 changes no agent behaviour. It converts the workspace into a git repository, puts a
guard in front of the deploy scripts, adds a dev runtime, turns the single-agent UI into an
agent shell, lays down test scaffolding, installs Impeccable, and runs four data spikes.
Everything is additive and behind flags or new files; the live runtime and CloudFront stack
are not redeployed this week.

## Architecture

```
develop ──► dev runtime (geospatial_agent_dev) ◄── local UI (vite + express dev servers)
   │                                                 │  AGENT_RUNTIMES = { default, dev, ... }
   │ scripts/promote.sh (eval + checklist + tag)      │
   ▼                                                 ▼
demo-stable ──► stable runtime (geospatial_agent_on_aws) ◄── CloudFront/ALB/Fargate (unchanged)
```

- Both runtimes share the S3 bucket (sessions are prefixed by session id) and the execution
  role (its trust policy is account-wide: `arn:aws:bedrock-agentcore:region:account:*`).
- Each runtime has its own ECR repository (`bedrock-agentcore-<agent_name>`), so a dev image
  can never replace the stable image.

## Components

### 1. Git layout (done)
- `demo-stable` = tag `deployed-2026-09-15` = live code including the ArcGIS MCP work.
- `develop` branched from it. `.gitignore` tracks `.kiro/{specs,hooks,skills,steering}` and
  ignores `.kiro/settings/`, `pr-drafts/`, `.env.dev`, `.env.stable`, the Impeccable binary
  and `.impeccable/` ephemera.
- The generated `geo_agent/.bedrock_agentcore/geospatial_agent_on_aws/Dockerfile` is tracked
  upstream and regenerated by `agentcore configure`; leave its local modification unstaged.

### 2. Deploy guard (done)
- `geo_agent/deploy_lib.sh`: `resolve_deploy_target` (target → `AGENT_NAME`, `ENV_FILE`,
  `AGENTCORE_BIN`) and `run` (executes, or prints with `*TOKEN=*`, `*SECRET*=*`, `*_KEY=*`,
  `*PASSWORD*=*`, OTLP headers redacted under `DRY_RUN=1`).
- `deploy.sh` and `deploy_with_langfuse.sh` source the lib, `cd` to their own directory,
  use `$ENV_FILE`, per-agent ECR names, `configure --name "$AGENT_NAME"` and
  `launch --agent "$AGENT_NAME"`.
- `AGENTCORE_BIN` defaults to `../.venv/bin/agentcore` (starter toolkit 0.3.3). The Homebrew
  `agentcore` (0.27.1, CDK-based CLI) has no `configure`/`launch` and is rejected.

### 3. Dev lane
- `.env.dev` is a copy of `.env` (created; gitignored). Same bucket, same role.
- First dev deploy: `DRY_RUN=1 DEPLOY_TARGET=dev ./deploy.sh`, then without `DRY_RUN`.
  The toolkit adds a second agent entry to `.bedrock_agentcore.yaml`; the stable entry is
  untouched because every command passes `--agent`.
- Local UI: `react-ui/backend/.env` gets `AGENT_RUNTIMES` with both ARNs;
  `npm run dev` in backend and frontend; `VITE_DEV_MODE=true` bypasses Cognito.

### 4. Agent switcher
Backend (`react-ui/backend/src/index.ts`):
- Parse `AGENT_RUNTIMES` (JSON) at startup into `Map<agentId, {arn, label, description, region}>`;
  fall back to `{ default: { arn: AGENT_RUNTIME_ARN } }`.
- One `BedrockAgentCoreClient` per region (region parsed from each ARN, as today).
- `GET /api/agents` → `[{ id, label, description }]` (public info only).
- `POST /api/agent/invoke` body gains `agentId?`; resolve ARN, 400 on unknown id.
- `POST /api/agent/stop-session` body gains `agentId?` for the same reason.
Frontend:
- `services/api.ts`: `listAgents()`, pass `agentId` on invoke/stop.
- `Chat.tsx`: `selectedAgentId` state persisted in `localStorage`; changing it calls the
  existing `handleSessionReset()` (new uuid, cleared layers; `MapView` remounts via `key`).
- `Navigation.tsx`: agent dropdown (label + one-line description). This is one of the six
  Impeccable-bounded surfaces; design it with `/impeccable shape` before coding.

### 5. Test scaffolding
- `geo_agent/tests/conftest.py` builds fixtures on the fly (no binary files in git): a
  256×256 float32 COG with rasterio, a 2 km square AOI GeoJSON, a 50-row synthetic LGND
  parquet with 256-dim embeddings via DuckDB.
- `geo_agent/tests/test_geometry.py` (`_slugify`, `bbox_around_point` closure and center),
  `test_raster_utils.py` (`clip_raster_v2` preserves CRS and produces a COG),
  `test_lgnd_handler.py` (imports `lambda_functions/lgnd_query/handler.py` and runs the
  similarity SQL against the synthetic partition using a local path instead of S3).
- `react-ui/frontend`: add `vitest` + `@testing-library/react` (dev deps, pinned);
  `src/utils/parsing.test.ts` with fixtures for complete JSON, truncated `input`, duplicate
  ids, `.geojson` vs `.tif` routing, date and cloud-cover extraction.
- `scripts/eval.py`: boto3 `InvokeAgentRuntime` against `--target dev|stable` (ARN read from
  `.bedrock_agentcore.yaml` by agent name), streams the response, extracts
  `{"toolUseId":...}` objects with the same brace-matching as the UI, compares tool-name
  order to `expected_tools` per prompt (subsequence match), fails on `Error:`.
  `scripts/golden_prompts.json` starts with the five README prompts plus one drawn-polygon
  prompt.
- `scripts/promote.sh`: `eval.py --target dev` → checklist (env vars present on runtime via
  `agentcore status`, smoke invoke, UI check, detector clean, `git status` clean) → `read`
  confirmation → `git switch demo-stable && git merge --ff-only develop && git tag
  deployed-$(date +%F)` → `DEPLOY_TARGET=stable CONFIRM_STABLE=yes ./deploy.sh` → back to
  `develop`.

### 6. Impeccable (installed)
- Skill at `.kiro/skills/impeccable` (v4.3.1, engine v0.1.5). `npm run design:check` in the
  frontend. Kiro hook `.kiro/hooks/impeccable-design-check.json` (PostToolUse on
  `fs_write|str_replace|fs_append`) tells the agent to run the detector after frontend edits.
- Remaining: `/impeccable init` (writes `PRODUCT.md`) and `/impeccable document` (writes
  `DESIGN.md`) are interactive and run by the builder in a Kiro session.
- Baseline: 6 findings; the two Roboto references and three side-tab borders are fixed in
  the `similarity-search` week when the layers panel and tool display are polished, not now.

### 7. Data spikes
Each spike is a throwaway notebook or script under `docs/spikes/` plus a one-page note with
the same headings: what was tried, what worked, access path, cost/latency observed, verdict.
- EMIT: plume GeoJSON from the EMIT open-data portal; one `EMITL2BCH4PLM` COG copied to the
  session bucket and rendered by TiTiler with `colormap_name=plasma`.
- 3DEP: one 1 m DEM GeoTIFF from the USGS `prd-tnm` bucket; `gdaldem hillshade` and a
  local-relief model; rendered through TiTiler.
- OPERA DISP-S1: Earthdata Login token → S3 temporary credentials for `us-west-2`; open one
  frame's HDF5 with `h5py`/`xarray` and read a 1-pixel displacement time series.
- Dark Vessels: MarineCadastre daily files for one month over Southern California →
  DuckDB parquet; one Sentinel-1 GRD scene from earth-search over the Channel Islands
  (assets are requester-pays in `eu-central-1`; read via `/vsis3/` with credentials); a
  two-parameter CFAR on VV in dB; count targets and AIS matches at scene time.

## Data models

`AGENT_RUNTIMES` example:
```json
{
  "default": { "arn": "arn:aws:bedrock-agentcore:us-east-1:ACCOUNT:runtime/geospatial_agent_on_aws-XXXX", "label": "Earth Analyst", "description": "Sentinel-2 analysis, change detection, protected areas" },
  "dev":     { "arn": "arn:aws:bedrock-agentcore:us-east-1:ACCOUNT:runtime/geospatial_agent_dev-YYYY", "label": "Earth Analyst (dev)", "description": "Development runtime" }
}
```

`golden_prompts.json` entry:
```json
{ "name": "vegetation-central-park", "prompt": "Show vegetation health for Central Park, New York",
  "expected_tools": ["find_address_candidates", "find_location_boundary", "get_best_geometry", "get_rasters", "run_bandmath", "display_visual"],
  "forbidden_text": ["Error:"] }
```

## Error handling

- Deploy guard exits 1 before any AWS call on misuse; `DRY_RUN` never calls `aws sts`.
- Backend returns 400 for unknown `agentId`, keeps SSE keepalive behaviour unchanged.
- `eval.py` treats a `RUNTIME_CRASH`-style error as a failure and prints the raw stream tail.

## Testing strategy

- Guard: shell-level tests already executed (no target, stable without confirm, bogus target,
  dev without `.env.dev`, dry runs for both targets and both scripts).
- Switcher: vitest for `listAgents` parsing; manual round-trip in the local UI against both
  runtimes; `eval.py --target dev` and `--target stable` both green.
- Scaffolding proves itself by running: `pytest -q`, `npm test`, `npm run design:check`,
  `python scripts/eval.py --target dev --dry-run` (prints the plan without invoking).
